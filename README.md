# Орбита · Планета успеха

React + GitHub Pages (интерфейс), Supabase Auth + Postgres + calendar-api (общие данные).
Рабочий адрес: https://merwine-ivan.github.io/orbita-calendar/

## Сборка

Node.js 22+, pnpm 10.

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm dev
```

Локальный просмотр: http://127.0.0.1:4174. Сервер просмотра отдаёт только собранную страницу.
`shared-dist/index.html` — интерфейс; `supabase/functions/calendar-api/index.ts` — серверная функция.
Для Pages копируйте собранную страницу в корневой `index.html` и публикуйте main.

В `supabase/public-config.json` хранится только публичный publishable key.
SUPABASE_SERVICE_ROLE_KEY и ORBITA_TEMP_PASSWORD задаются только в серверных secrets.
Серверная функция проверяет пользователя через Auth и действующие права из orbita_profiles.
Прямые обращения anon/authenticated к таблицам запрещены; RLS включён.
`verify_jwt=false` у Edge gateway сохраняется, поскольку функцию защищает собственная проверка Auth.

## Права

- Главный admin: учётные записи, субадмины, общий журнал, аудит и полная резервная копия.
- Субадмины: журнал, группы и управление доступом преподавателей; без управления другими администраторами.
- Преподаватели: просмотр общего журнала, свои созданные группы и назначенные группы по разрешённым предметам.
- Удаление занятия — корзина; удаление группы — архив. Данные остаются для восстановления.

Учётные записи создают администраторы. При первом входе и сбросе пароль обязательно меняется.
Сессия сохраняется в sessionStorage текущей вкладки до восьми часов. При сетевом сбое обновление можно повторить без потери refresh token.

## Резервная копия

Главный admin → «Резервная копия» → «Скачать полную копию JSON».
Снимок включает все месяцы, учеников, расписание, посещаемость, отчёты, архив и корзину.
Он читается одним SQL-запросом: связанные записи соответствуют одному состоянию базы.
Профили включают ID, имя, логин, роль, предметы и disabled для связи с занятиями; паролей и токенов нет.
Файл содержит персональные данные, храните его в закрытой папке. Не коммитьте копии в GitHub.

Это прикладная копия, а не полный дамп Supabase: Auth, секреты, аудит и история импортов не включаются.
Восстановление доступно главному admin в этом же разделе. Перед записью показывается план, проверяются связи и версии; безопасный режим сохраняет действующие записи. Замена совпадающих записей включается отдельно. Учётные записи сопоставляются по ID/логину и не создаются из копии.

## Изменения базы

SQL в `supabase/migrations/` хранится вместе с кодом. Миграция 20261018195000 добавляет
согласованный снимок журнала, доступный только service_role, и закрывает клиентское выполнение rls_auto_enable.
Применяйте её до публикации calendar-api с маршрутом backup. Миграция не изменяет записи журнала.

## Проверки

`pnpm test`: роли, запреты обхода API, конфликт версий, корзина, расписание, CSV, резервные копии и гонки обновления сессии.
CI проверяет PR и main и собирает актуальный интерфейс. Сборку Edge Function необходимо опубликовать отдельно в Supabase.

## Импорт, восстановление и контакты

Администраторы открывают «Группы → Импорт CSV»: шаблон, серверный предпросмотр, явное подтверждение и атомарное сохранение. CSV поддерживает группы, учеников, контакты, недельное расписание и датированные занятия с посещаемостью/отчётом. Контакты видны менеджерам и назначенным преподавателям, прочим преподавателям сервер возвращает только имя и код.

Главный admin открывает «Резервная копия → Восстановить из JSON». Безопасный режим добавляет недостающее; замена состояния совпадающих записей включается отдельно. Записи вне файла и дополнительные ученики сохраняются. Auth-аккаунты и пароли не меняются. Преподаватели сопоставляются по ID или прежнему логину. Перед каждой записью RPC сохраняет полную копию в orbita_imports. Последние 20 копий скачиваются из истории. Ограничение одной операции: CSV 1 МБ; JSON 5 МБ, до 1000 групп / 5000 занятий.

Preview digest включает исходный файл, режим, изменения и версии всех записей. RPC блокирует запись на время сверки и транзакции; конфликт отменяет операцию целиком. Повтор запроса с тем же requestId/digest идемпотентен. Функция доступна только service_role, повторно проверяет действующую роль и отзыв сессии.

Миграция: 20261019095807_atomic_data_transfer.sql. Перед публикацией применить миграцию и обновить calendar-api, затем GitHub Pages. Не применять восстановление к рабочим данным для тестирования; SQL-проверки выполнять в транзакции с ROLLBACK.

## Единая карточка ученика и планирование

Раздел «Ученики» группирует членства по personId (по умолчанию исходный ID ученика). ФИО само по себе не означает одного человека. Администратор вручную выбирает проверенные карточки и основную; операция показывает план и сохраняет before-image. Исходные ID членств и посещаемость не меняются. Существующие данные не объединяются при публикации.

Преподаватель редактирует общие данные только учеников своих активных назначенных групп. Объединение и добавление существующей карточки в другую группу выполняет администратор. Коды остаются локальными для групп. Общие ФИО и контакты редактируются через «Ученики», чтобы обновление применялось ко всем связанным группам одной транзакцией. Добавление членства защищено сверкой версий всего журнала.

«Группы → В календарь» и «Добавить занятия · период» поддерживают 1–4 недели (ровно 7×N дней от даты), а также месячные периоды. Новый состав группы сначала сохраняется; затем открывается отдельный серверный предпросмотр занятий. Генерация идемпотентна и не воскрешает удалённые занятия. Массовая запись выполняется атомарно с резервной копией.

Предупреждения пересечений учитывают фактического преподавателя, группу и personId общих учеников. Соседние интервалы не пересекаются; отменённые/удалённые занятия исключены. Создание/перенос с пересечением требует явного подтверждения. Сохранение отчёта старого занятия не блокируется историческим пересечением. Для больших наборов показываются до 200 найденных пересечений. Совпадения ФИО без подтверждённой связи не считаются общими учениками.
