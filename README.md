# Орбита · Планета успеха

React + GitHub Pages (интерфейс), Supabase Auth + Postgres + calendar-api (общие данные).
Рабочий адрес: https://merwine-ivan.github.io/orbita-calendar/

## Сборка

Node.js 22+, pnpm 10.

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm dev
```

Локальный просмотр: http://127.0.0.1:4174. Сервер просмотра отдаёт только собранную страницу.
`shared-dist/index.html` — интерфейс; `supabase/functions/calendar-api/index.ts` — серверная функция.
Для Pages копируйте собранную страницу в корневой `index.html` и публикуйте main.

В `supabase/public-config.json` хранится только публичный publishable key.
SUPABASE_SERVICE_ROLE_KEY и ORBITA_TEMP_PASSWORD задаются только в серверных secrets.
Серверная функция проверяет пользователя через Auth и действующие права из orbita_profiles.
Прямые обращения anon/authenticated к таблицам запрещены; RLS включён.
`verify_jwt=false` у Edge gateway сохраняется, поскольку функцию защищает собственная проверка Auth.

## Права

- Главный admin: учётные записи, субадмины, общий журнал, аудит и полная резервная копия.
- Субадмины: журнал, группы и управление доступом преподавателей; без управления другими администраторами.
- Преподаватели: просмотр общего журнала, свои созданные группы и назначенные группы по разрешённым предметам.
- Удаление занятия — корзина; удаление группы — архив. Данные остаются для восстановления.

Учётные записи создают администраторы. При первом входе и сбросе пароль обязательно меняется.
Сессия сохраняется в sessionStorage текущей вкладки до восьми часов. При сетевом сбое обновление можно повторить без потери refresh token.

## Резервная копия

Главный admin → «Резервная копия» → «Скачать полную копию JSON».
Снимок включает все месяцы, учеников, расписание, посещаемость, отчёты, архив и корзину.
Он читается одним SQL-запросом: связанные записи соответствуют одному состоянию базы.
Профили включают ID, имя, логин, роль, предметы и disabled для связи с занятиями; паролей и токенов нет.
Файл содержит персональные данные, храните его в закрытой папке. Не коммитьте копии в GitHub.

Это прикладная копия, а не полный дамп Supabase: Auth, секреты, аудит и история импортов не включаются.
Автоматическое восстановление через UI пока не реализовано. Восстановление требует проверки JSON,
создания/сопоставления аккаунтов и замены ID преподавателей до загрузки групп и занятий в одной транзакции.
Нельзя просто загрузить файл поверх рабочей базы без проверки связей и версий.

## Изменения базы

SQL в `supabase/migrations/` хранится вместе с кодом. Миграция 20261018195000 добавляет
согласованный снимок журнала, доступный только service_role, и закрывает клиентское выполнение rls_auto_enable.
Применяйте её до публикации calendar-api с маршрутом backup. Миграция не изменяет записи журнала.

## Проверки

`pnpm test`: роли, запреты обхода API, конфликт версий, корзина, расписание, CSV, резервные копии и гонки обновления сессии.
CI проверяет PR и main и собирает актуальный интерфейс. Сборку Edge Function необходимо опубликовать отдельно в Supabase.
